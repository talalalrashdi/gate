# صفحات الأخطاء العربية

صفحات MVC مستقلة عن قاعدة البيانات وAPI، بنفس خط البوابة المحلي والخنجر والأخضر والخلفية الفاتحة. لا تحمل ملفات JavaScript الخاصة بمحتوى البوابة، ولا ترسل طلبات بيانات. التصميم مشترك، والنص والأيقونة يتغيران حسب الحالة.

| الرابط | الحالة |
|---|---|
| `/errors/400` | طلب غير صحيح |
| `/errors/401` | تعذر التحقق من حساب Windows |
| `/errors/403` | لا توجد صلاحية |
| `/errors/404` | الصفحة غير موجودة |
| `/errors/405` | طريقة الطلب غير مسموحة |
| `/errors/408` | انتهاء مهلة الطلب |
| `/errors/429` | طلبات كثيرة |
| `/error` أو `/errors/500` | خطأ غير متوقع |
| `/errors/502` | خطأ اتصال بالخدمة المرتبطة |
| `/errors/503` | الخدمة غير متاحة |
| `/errors/504` | انتهاء مهلة الخدمة المرتبطة |

الروابط تعيد HTTP status الحقيقي، وليست صفحات نجاح. الرموز غير المعروفة تتحول إلى500. جميع الروابط تراعي IIS application path باستخدام Url.Content. لا returnUrl ولا تحويل إلى عناوين خارجية.

طلبات التصفح التي تقبل HTML تعيد تنفيذ الأخطاء الفارغة داخل نفس الطلب، فتبقى الصفحة المطلوبة في شريط العنوان (مثل404). استثناءات Production تستخدم `/error` الموجود أصلًا؛ Development يحتفظ بسلوك التشخيص الخاص به. صفحات JSON وطلبات API لا تستبدل بواجهة HTML. أخطاء تحميل البيانات داخل أقسام البوابة تستمر برسائلها وإعادة المحاولة الخاصة بها. صفحة401 لا تغير إعداد Windows authentication ولا تتجاوز طلب المتصفح لتسجيل الدخول؛ صفحة403 لا تمنح صلاحية جديدة.

إعادة المحاولة تعيد تحميل الرابط الحالي، ولا تعيد إرسال عمليات كتابة تلقائيًا من JavaScript. رقم المرجع يعرض Activity ID أو TraceIdentifier للطلب، دون رسالة الاستثناء أو المسار أو stack trace.

أخطاء IIS التي تقع قبل تشغيل ASP.NET Core مثل500.19/500.30، أو رفض Windows authentication قبل وصول الطلب للتطبيق، لا يستطيع MVC رسمها. إذا استبدل IIS محتوى الأخطاء الصادر من التطبيق، اضبط IIS HTTP Errors على `existingResponse="PassThrough"` حسب إعدادات الاستضافة، دون تعطيل Windows authentication أو استخدام custom redirect يلغي challenge.

الملفات: Models/PortalError.cs، Views/Home/Error.cshtml، css/error-pages.css، js/error-pages.js. اختبارات محلية: البناء دون تحذيرات؛11 رمزًا وno-store وRTL؛404 تلقائي؛عدم تغيير JSON؛معاينة403 و503 وإعادة المحاولة في المتصفح. لا تغييرات على قاعدة البيانات أو API.
