# التوجيهات السامية

The header opens a read-only timeline backed by `CompanyPortal.Portal.FixedOrders`. The API calls `Portal.FixedOrders_getAll`; it requires Windows authentication and a currently registered, active portal employee. Creation/editing is now available in the protected [administrator editor](FIXED_ORDERS_ADMINISTRATION.md), added by migration 027. Employee timeline behavior remains unchanged.

## Database

Apply `Backend/Database/Scripts/021_FixedOrders.sql` to an existing CompanyPortal database. The script creates the table if absent and creates or updates the procedure; it does not seed directives. Fresh-install `Deployment/CompanyPortal-Setup.sql` includes migrations through 021.

| Column | Type | Behaviour |
|---|---|---|
| FixedOrderID | bigint IDENTITY(1,1), primary key | Required identity |
| Timestamp | date NULL | Manually entered primary date and displayed year |
| Timestamp2 | date NULL | Returned for future use; does not determine the year |
| ContentBefor | nvarchar(500) NULL | Previous text; original spelling retained |
| ContentAfter | nvarchar(1000) NULL | Card title and replacement text |
| ContentText | nvarchar(1000) NULL | Plain-text template |
| TimestampType | int NOT NULL | Meaning not yet confirmed; stored and returned unchanged |

No defaults are assigned to dates or TimestampType. No Active column or automatic timestamp was added to this explicitly agreed schema. Every row is returned, ordered by primary date descending, then FixedOrderID descending; undated rows appear last. Supply TimestampType when manually adding a row; this implementation does not invent its meaning.

## Rendering

`GET /api/fixed-orders` returns the seven fields plus `year` derived only from Timestamp. IDs are JSON strings to preserve bigint precision in JavaScript; dates are ISO date-only strings without timezone conversion. Responses and requests use no-store.

- Every exact `ds{0}de` in ContentText becomes ContentBefor, in amber.
- Every exact `ss{1}se` becomes ContentAfter, in green.
- Normal surrounding text retains its normal colour. Templates with only the first marker work.
- Replacements are inserted once as text. HTML and markers inside replacement values are not interpreted.
- Null replacement values become empty text; null ContentText gives an empty body.
- Empty ContentAfter uses the title **توجيه سامٍ**. Null Timestamp uses **التاريخ غير محدد** and the year group **غير محدد السنة**.

Each opening reads current data, clears earlier rows, and displays loading, empty or retryable error states. Closing cancels the request and clears rendered content. No directive data is saved in browser storage. The timeline supports year navigation, keyboard focus and Escape to close.

## Deployment and checks

Republish both applications after applying migration 021. Older CurrentData SQL exports and previously published Airgap folders have not been regenerated by this feature; apply pending migrations in order to those installations and republish. Do not reimport a fresh-install script into an existing installation.

Local checks passed: both Release builds without warnings, anonymous rejection and inactive-employee rejection, date/year/null mapping, Swagger, exact/repeated/before-only markers, literal HTML safety, large IDs, request cancellation/error handling, browser year navigation, distinct colours and keyboard close. The frontend parity and offline asset checks also passed.

`tools/verify-fixed-orders.mjs` tests the real renderer without SQL. `Backend/tools/Test-FixedOrders.ps1` tests the local API using explicitly marked temporary rows. Its `-KeepFixture` option retains those rows for browser checks; always finish with `-Cleanup`. Local acceptance fixtures were removed.

The user subsequently requested persistent sample data. `Backend/Database/Development/007_SeedFixedOrders.sql` provides ten fictional Arabic rows across 2000–2004 and 2025–2026, avoiding duplicates on rerun. At the user's request, the sample labels and words describing text as experimental were removed from displayed titles and bodies; these remain fictional development records, not historical directives. It includes both-marker and before-only templates and one Timestamp2 value. TimestampType=1 is a sample value with no confirmed business meaning. These samples were applied locally; they are separate from production migrations and older offline exports.
