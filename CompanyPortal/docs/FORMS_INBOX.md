# وارد نظام الاستمارات

بطاقة نظام الاستمارات تعرض العنوان، اسم المرسل، تاريخ ووقت الإرسال (توقيت عمان)، مع لون خمري للعناصر غير المفتوحة ولون عادي للمفتوحة. أزيلت بطاقتا قيد المراجعة والمسودة. الشارة تعد غير المفتوح حسب المصدر، وتختفي عند صفر. لا تُحسب من عناصر الصفحة المعروضة.

التاريخ والوقت في يسار صف الاستمارة، والعنوان والمرسل في اليمين لتقليل الارتفاع. أزيلت رسالة إعداد رابط العينة من البطاقة؛ تظل نافذة المعاينة موسومة بوضوح وتبقى أخطاء الاتصال والحالة الفارغة ظاهرة.

يعرض الوارد خمسة عناصر في الصفحة، بالتباعد المختصر السابق ودون تمرير داخلي. يحتفظ نظام صفحات البطاقات بارتفاع أطول صفحة في القائمة، بحيث لا تنكمش البطاقة أو تتمدد عند التنقل بين الصفحات. شارة «جديد» مستقلة عن اللون وحالة الفتح: لا تظهر للعناصر الموجودة في أول تحميل، حتى لو كانت غير مفتوحة؛ تظهر لمدة60ثانية فقط عند اكتشاف FormId جديد غير مفتوح في تحديث لاحق، وتُزال فور إعلان المصدر أنه مفتوح حتى لو لم تنته الدقيقة. التحديث الدوري والعودة للتبويب لا يعيدان تشغيل مؤقت عنصر معروف، ولا تحتاج إزالة الشارة طلب API. إعادة تحميل الصفحة تبدأ جلسة عرض جديدة. اللون الخمري والعداد يتبعان IsOpened في Formsdb فقط.

## عقدا الإجراءات

في CompanyPortal:

- `Portal.Forms_Inbox_Get @UserId int, @FormId bigint=NULL`: يعيد `FormId bigint`, `Title nvarchar(1000)`, `SenderName nvarchar(500)`, `SentAt datetime`, `IsOpened bit`, `IsSample bit`. NULL يعني الوارد كاملًا مرتّبًا بالأحدث. FormId المحدد يُستخدم للتحقق من صلاحية فتح رابط الاستمارة. يجب دائمًا التصفية بالموظف وActive في المصدر.
- `Portal.Forms_UnreadCount_Get @UserId int`: يعيد صفًا واحدًا، عمود `UnreadCount int` لعدد العناصر النشطة غير المفتوحة المصرح بها لنفس الموظف.

API `GET /api/forms` يحل NTName إلى UserId بواسطة Security.User_getByUsername، ثم ينفذ الإجراءين في طلب متصفح واحد. المعرف يُرسل كنص للحفاظ على bigint. لا يقبل UserId من العميل. `GET /api/forms/{id}/open` يعيد التحقق من المصدر قبل التوجيه لتطبيق الاستمارات. كل طلب يتطلب Windows authentication وتسجيل موظف نشط؛ الاستجابات private/no-store.

Formsdb هو صاحب حالة IsOpened. البوابة للقراءة فقط: لا يغيّر فتح العنصر الحالة أو UserReads، ولا ينقص العداد حتى يبلّغ المصدر عن الفتح. يجب أن يعيد SP القائمة وSP العداد حالة المصدر المتسقة نفسها، بما في ذلك العناصر المفتوحة خارج البوابة.

## قاعدة التطوير والنقل

1. قاعدة موجودة: طبّق `Backend/Database/Scripts/040_FormsInbox.sql`. ينشئ عقدين فارغين إذا لم يكونا موجودين؛ لا يستبدل adapter تم تركيبه.
2. محليًا فقط: `Backend/Database/Development/022_CreateSampleFormsdb.sql` ينشئ Formsdb مع علامة CompanyPortalDevelopmentFixture وجدول dbo.FormInbox وخمس عينات للموظف الحالي، ثم يربط الإجراءين بالمصدر المحلي. يرفض قاعدة غير موسومة. بيانات المثال تحفظ حالة الفتح في Formsdb. إعادة التنفيذ لا تضاعف العينات ولا تعيد حالة الفتح.
3. في الشبكة الداخلية: عدّل SELECTs في الإجراءين إلى الجداول الفعلية ومعرف الموظف الحقيقي. لا تنفذ ملف Development على قاعدة الاستمارات الحقيقية. اجعل IsSample=0. امنح هوية API صلاحية EXECUTE المطلوبة والوصول للمصدر وفق إعداد SQL الداخلي؛ لا يحتاج الموظفون وصول SQL مباشرًا.

Setup الجديد يشمل040 وعقود التكامل فقط؛ لا ينشئ Formsdb الوهمي تلقائيًا ولا يصدّر بياناته. ملفات CurrentData القديمة لم تتغير. يلزم نقل الواجهة وAPI وتطبيق040 وضبط adapter المصدر.

## رابط التطبيق

في Backend/CompanyPortal.Api/appsettings.json:

```json
"Forms": {
  "ItemUrlTemplate": "https://FORMS-SERVER/forms/open?id={id}",
  "AllowSamplePreview": false
}
```

الرابط مجرد مثال؛ استخدم مسار التطبيق الحقيقي. يُستبدل {id} بمعرف المصدر. لا يُقبل عنوان من المتصفح؛ يسمح فقط http/https دون بيانات دخول. الرابط الفارغ يعرض حالة غير مهيأة ويمنع فتح عناصر حقيقية. إذا اختلف تركيب رابط النظام الداخلي يمكن تعديل محول الرابط في API.

Development يفعّل AllowSamplePreview للعينات الموسومة فقط: تفتح نافذة محلية واضحة، لا تدعي فتح التطبيق ولا تغير IsOpened. Production افتراضيًا لا يفتح هذه المعاينة. لا يوجد رابط مؤقت مخادع أو endpoint لتغيير حالة الفتح في البوابة.

## التحديث والتحقق

طلب أول عند تحميل الصفحة، ثم كل60–65ثانية بعد اكتمال السابق، دون تداخل. لا polling أثناء إخفاء التبويب؛ العودة تجلب الحالة فورًا. فشل الاتصال يؤخر المحاولة حتى5دقائق؛401/403 يمسح البيانات، ولا يستبدل الخطأ بعداد صفر. الاستجابة غير المتغيرة لا تعيد إنشاء عناصر القائمة. الصفحات تستخدم نظام صفحات البطاقة الحالي. لا SignalR أو تبعيات جديدة.

`Backend/tools/Test-FormsInbox.ps1` يختبر العقد والعداد وحالة المصدر والعزل والفتح/عدم النشاط وغياب الرابط ورفض المجهول وSwagger، بعناصر مؤقتة فريدة تُحذف بدقة في النهاية. يجب أن يعمل API محليًا على5091 مع Development وعينات Formsdb.

## فتح التطبيق والعدد الإجمالي

تحت عنوان البطاقة يظهر «عدد الاستمارات» وهو عدد كل عناصر الوارد المصرح بها في الاستجابة، لا عدد الصفحة أو النوع المحدد. شارة الأيقونة تظل لغير المفتوح من SP العداد. لا يضاف SP أو طلب إضافي لحساب الإجمالي؛ الإجراء الحالي يعيد الوارد كاملًا. إذا أصبح المصدر مقسمًا على الخادم مستقبلًا يجب إرجاع إجمالي المصدر صراحةً.

زر «فتح الاستمارات» يستخدم `Forms:AppUrl` في إعدادات API، مستقلاً عن ItemUrlTemplate المستخدم لعنصر محدد. مثال توضيحي (استبدله بعنوان التطبيق الحقيقي):

```json
"Forms": {
  "AppUrl": "https://APP-SERVER/",
  "ItemUrlTemplate": "",
  "AllowSamplePreview": false
}
```

الرابط يعود مع الوارد في appUrl بعد التحقق من http/https وغياب بيانات دخول في العنوان، ويفتح في علامة تبويب جديدة. الرابط الفارغ أو غير الصالح يعطل الزر مع تلميح واضح. الواجهة تتحقق مجددًا من الرابط، وتمسحه مع بيانات الوارد عند انتهاء الصلاحية أو إخفاء الصفحة. لا يتغير المصدر أو حالة الفتح عند فتح التطبيق مباشرةً. الزر في عنوان البطاقة بمظهر زر فتح البريد، ويظهر عند المرور أو التركيز داخل البطاقة؛ الإجمالي تحت العنوان.


## أنواع الاستمارات وتخطيط خمس صفوف (28 أكتوبر 2026)

يعيد `Portal.Forms_Inbox_Get` عمود `Purpose` (`nvarchar(100)` في المصدر المحلي): «للعلم» أو «للإجراء». يمرره API كـ `purpose` وتعرض الواجهة شارة زرقاء للعلم وذهبية للإجراء، مستقلة عن حالة الفتح وشارة «جديد». لا توجد قائمة تصفية جديدة. الإجراءات القديمة التي لم تُرجع العمود بعد تظل تعمل وتستخدم «للعلم» مؤقتًا؛ استبدل SELECT في الإجراء عند ربط المصدر الحقيقي، ولا تستنتج النوع من عنوان الاستمارة أو حالة القراءة.

للقاعدة المحلية الموجودة، شغّل `Backend/Database/Development/027_FormsInboxPurpose.sql`؛ لا يعمل إلا مع Formsdb المعلّمة كعينة تطوير. يضيف العمود ويعين الأنواع لخمسة الأمثلة الموجودة، ولا يعيد تعيين الأنواع عند إعادة تشغيله. إنشاء العينة الجديدة في 022 يتضمن العمود والأنواع كذلك. لا يلزم تعديل جداول CompanyPortal أو إجراء ترحيل إنتاجي؛ العقد الفارغ في 040 يتضمن العمود، ولا يستبدل محول مصدر مثبتًا.

الاستمارات والبريد يعرضان خمسة عناصر في الصفحة، بارتفاع ثابت 80px للصف و4px بين الصفوف؛ العنوان الطويل محدود بسطرين. ارتفاع البطاقة الخارجية لا يتغير في الصفحة الأخيرة، ولا تتمدد رسالة واحدة لتملأ المساحة. عداد غير المقروء ومصدره وسلوك الفتح والتحديث كما هي.


## قراءة المعاينة المحلية (28 أكتوبر 2026)

فتح **المعاينة المحلية** يغيّر حالة العنصر في ذاكرة التبويب إلى مقروء، يزيل «جديد» ويقلل الشارة مرة واحدة. تُحفظ هذه الحالة خلال التحديثات الدورية والعودة للتبويب، وتُمسح بإعادة تحميل الصفحة أو فقد الصلاحية 401/403. لا تُكتب في Formsdb أو UserReads. عند وصول حالة مقروء من المصدر لا يتم إنقاص العداد مرتين. هذا استثناء خاص بالمعاينات للتطوير؛ الروابط الحقيقية تظل تتبع حالة IsOpened وعداد المصدر، كما سبق.

صفوف الاستمارات والمراسلات والبريد المقروء لها حدود واضحة، وتبقى الألوان المميزة لغير المقروء وخمس صفوف ثابتة الارتفاع. اختبار `node CompanyPortal/tools/verify-inbox-previews.mjs` يغطي الفتح، التكرار، التحديث، تأكيد المصدر، مسح الصلاحية وعدم إرسال عمليات كتابة.
