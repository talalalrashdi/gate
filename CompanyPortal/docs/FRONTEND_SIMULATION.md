# وضع محاكاة أحداث البوابة

يتيح تجربة ظهور المواد الجديدة دون تعديل قواعد البيانات أو إرسال رسائل حقيقية.

زر **دليل الهاتف — حالات متنوعة** يفتح نفس ورقة البحث بستة أشخاص توضيحيين: موظفون، متعاقد، متدرب ومتقاعد؛ موجود/غير موجود؛ موظف غير موجود وله مكلف يمكن الانتقال إلى بطاقته؛ أشخاص بلا بريد وشخص بلا رقم مكتب أو معلومات إضافية. البحث والمزيد والمكلف تعمل محليًا دون طلبات Dalil أو بيانات محفوظة. أيقونة البريد تعرض معاينة عنوان فقط ولا تفتح OWA. شريط واضح يبين المحاكاة، وزر **العودة للدليل الحقيقي** أو **مسح المحاكاة** يزيل العينات؛ إعادة تحميل الصفحة تزيلها كذلك. ظهور الأداة يتبع Diagnostics:SimulationEnabled.

إغلاق × للقرار المحاكى في التنويه يخفيه من هذا القسم حتى مسح المحاكاة أو إعادة تحميل الصفحة، ويبقيه في القرارات. لا يرسل طلب إخفاء إلى API. القرارات الحقيقية تحفظ الإخفاء لكل موظف في قاعدة البيانات، وتبقى مخفية بعد إعادة التحميل. عنوان الشارة يعرض النوع الفعلي للقرار.

## التشغيل والإيقاف

في `Frontend/CompanyPortal.Web/appsettings.Development.json`، ضمن Diagnostics:

```json
"Diagnostics": {
  "SimulationEnabled": true
}
```

`Diagnostics:Enabled` إعداد قديم غير مستخدم وأُزيل من أمثلة النشر. `SimulationEnabled` قيمته **false** في الملف الأساسي و**true** في Development؛ لذلك لا تظهر الأداة في Production إلا عند تفعيلها صراحة. لتشغيل المحاكاة ضع true، ثم أعد تحميل الصفحة. إذا لم يلتقط التشغيل التغيير فأعد تشغيل التطبيق/مجمع IIS. يمكن استخدام `appsettings.Production.json` أو متغير البيئة `Diagnostics__SimulationEnabled` لنفس القيمة. لا يمكن تشغيلها من رابط أو query string.

عند false لا ترسل صفحة MVC لوحة المحاكاة أو ملف JavaScript/CSS الخاصين بها. المستخدم الذي لديه صفحة مفتوحة من قبل التغيير يحتاج إعادة تحميلها لإزالة أدواتها.

## الاستخدام

اضغط أيقونة **وضع المحاكاة** بجانب صورة المستخدم لفتح القائمة المنسدلة. اكتب عنوانًا اختياريًا ثم اختر:

| الزر | ما يظهر |
| --- | --- |
| قرار جديد | قرار بالنوع المختار في قائمة الاختبار؛ يظهر في القناة المطابقة لإعدادات الإدارة |
| قرار تنويه جديد | قرار تنويه وقسم تنويه العائم؛ يتم إظهاره للاختبار |
| قرار إعلان / تنبيه جديد | قرار إعلان والتنبيه العائم؛ يتم إظهاره للاختبار |
| خبر جديد | خبر في العناوين وقائمة أخبار عامة ومنطقة الخبر المحدد |
| خبر عاجل | خبر مميّز بصفته خبرًا مهمًا في العرض الموجود |
| مسح المحاكاة | إزالة المواد الوهمية واستعادة محتوى القرارات والأخبار الحقيقي المحمّل |

تظهر المواد بعنوان يبدأ بـ `[محاكاة]`. أُزيل الإشعار المنفصل «محاكاة محلية»؛ تظهر المواد في أقسامها الفعلية فقط، وتظهر نتيجة الاختبار داخل قائمة المحاكاة.

قرار المحاكاة يفتح معاينة نصية محلية بدل PDF؛ فتحه يختبر تغيير حالة القراءة والخمري/الأسود وعلامة جديد في القناتين، **دون POST أو سجل قراءة في SQL**. لا يرسل المتصفح معرّف `simulation-*` إلى API. الإغلاق والانتقال بين التنويهات لا يسجلان القراءة.

البحث في القرارات **بالعنوان فقط**. النوع يُختار من قائمة **نوع القرار**. يسري البحث والتصنيف على مواد المحاكاة أيضًا، لذلك قد يلزم اختيار «جميع الأنواع» أو مسح البحث لرؤيتها في القائمة.

## حدود الاختبار

- بيانات مؤقتة في ذاكرة التبويب فقط؛ حد 20 قرارًا و20 خبرًا للمحاكاة. إعادة تحميل الصفحة تمسحها، ولا يوجد localStorage أو إنشاء سجلات SQL.
- مواد القرارات الوهمية تبقى مع التحديث الدوري للقائمة في نفس التبويب. الأخبار الوهمية تضاف إلى الصفحة الأولى؛ لا تحل محل أي خبر حقيقي في تلك الصفحة. أسهم الأخبار تستمر باستخدام صفحات المصدر الحقيقية.
- لا تحاكي هذه الأدوات EWS أو صلاحيات AD أو اتصال SQL أو وصول أحداث SignalR/SSE. فحص المسار الحقيقي يحتاج بيانات مصدر حقيقية واختبارًا منفصلًا.
- لا يحتاج هذا التعديل SQL جديدًا. انشر frontend وAPI معًا لأن المحاكاة تقرأ أنواع الإدارة من GET /api/decisions/notice-rules. اضبط القيمة لكل بيئة، واتركها false في الاستخدام المعتاد.
- هذا المفتاح يطبق على جميع زوار نسخة frontend عند تفعيله؛ الأدوات لا تحتوي بيانات سرية ولا تمنح صلاحيات إضافية.

## إضافة اختبارات لاحقًا

اللوحة تنشر حدث `portal:simulate` محليًا بعملية وعنوان ومعرّف تسلسلي. وحدتا القرارات والأخبار تستمعان إليه فقط عند وجود لوحة MVC التي يسمح بها الإعداد. يمكن إضافة زر ومستمع مماثل لاختبار قسم آخر، مع المحافظة على بادئة المحاكاة وعدم استدعاء API للمواد الوهمية ودعم reset.

## قواعد الإدارة والإظهار التلقائي

عند فتح قائمة المحاكاة لأول مرة تُقرأ قواعد القناتين عبر نقطة قراءة محمية بحساب Windows وتسجيل المستخدم. يُحفظ الرد في ذاكرة الصفحة؛ لا طلب قواعد لكل ضغطة. استخدم **تحديث إعدادات الأنواع** بعد تغيير الإدارة أثناء نفس جلسة الاختبار.

اختر نوع القرار للاختبار ثم اضغط **قرار جديد**. إذا كان النوع ضمن القنوات النشطة يفتح التنويه أو التنبيه المناسب تلقائيًا؛ وإلا يظهر القرار في قائمته دون نافذة قناة. زرا تنويه/تنبيه يختاران نوعًا من إعدادات قناتهما، ولا يتجاوزان إيقاف القناة. الفترة العامة بالأيام تُستخدم للمادة الجديدة؛ ليس لها استثناء محفوظ في قاعدة البيانات.

في التشغيل الحقيقي، أول تحميل يبقى على سياسة الإخفاء الحالية؛ بعده تؤدي مادة جديدة غير مقروءة ومصرح بها وداخل الفترة المحددة إلى إظهار القناة تلقائيًا عند التحديث الدوري (نحو دقيقة). بداية فترة مستقبلية لمادة منشورة يمكن أن تفتح القناة أيضًا. لا يتكرر الظهور لنفس المادة بسبب تحديث القائمة أو فتحها وإغلاقها. علامة جديد شارة صغيرة أعلى العنوان بلون فاتح ونص داكن، وتختفي عند القراءة.

قائمة المحاكاة تستخدم popover للظهور فوق التقويم والتنبيهات، وتغلق بالضغط خارجها أو Escape. قائمة نوع القرارات ملاصقة لحقل البحث، دون عنوان مرئي إضافي، مع تسمية لقارئ الشاشة.

## تصحيح استقلال القنوات

كل اختبار يفتح القنوات الموجودة في نتيجة مطابقة نوع القرار فقط، ولا يفتح القناتين بسبب زر عام. مثال الإعداد الحالي: تعميم/تنويه يفتح التنويه وحده، وإعلان يفتح التنبيه وحده. بعد إغلاق قسم، اختبار النوع الآخر لا يعيد فتح القسم المغلق. يمكن إبقاء القسمين مفتوحين بعد اختبارين مختلفين، والتنويه يبقى أعلى التنبيه. «مسح المحاكاة» يخفي القناتين أيضًا لبدء اختبار مستقل. القوائم المنسدلة للأنواع تستخدم خطًا14px.


## Outlook: أزرار جاهزة بلا إدخال

من أيقونة المحاكاة بجانب الصورة، اختر **عرض البريد والجدول والمهام** لعرض خمس رسائل (ثلاث غير مقروءة)، مواعيد اليوم ومواعيد موزعة على الشهر، وخمس مهام بحالات مختلفة. جميع أزرار Outlook تعمل مباشرة حتى دون الضغط على زر البداية.

| المجموعة | الاختبارات الجاهزة |
| --- | --- |
| البريد | رسالة جديدة مع زيادة العداد والإشعار، قراءة رسالة، حذف رسالة، صندوق فارغ |
| التقويم | موعد اليوم، تعديل، إلغاء، طوال اليوم، تقويم فارغ؛ التنقل بين الأيام والشهور |
| المشترك | تقويم المدير، موعد خاص بلا تفاصيل، وضع التحديث اليدوي، سحب صلاحية التقويم والعودة لتقويمي |
| المهام | مهمة جديدة، اكتمال أول مهمة، حالات متنوعة (متأخرة/اليوم/قادمة/بلا تاريخ)، قائمة فارغة؛ المرشحات الحقيقية |
| الاتصال | انقطاع يخفي البيانات والعدادات، عودة الاتصال تستعيد العينات، إنهاء محاكاة Outlook يعيد الاتصال الحقيقي |

فتح رسالة أو زر فتح البريد يعرض معاينة محلية ولا يفتح OWA ولا يغير حالة رسالة حقيقية. اكتمال المهمة وحذف الرسالة يحاكيان تحديثًا واردًا من Exchange؛ لا يضيفان تحريرًا حقيقيًا للواجهة. إشعارات المواعيد والمهام تستخدم قائمة الإشعارات الموجودة. المهام تبقى مهام المستخدم حتى عند اختيار تقويم المدير؛ اكتشاف المهام المشتركة والتحرير غير منفذين.

تُغلق قناة البريد الحقيقية عند بدء محاكاة البريد، وقناة الجدول عند بدء محاكاة الجدول. التنقل والتصفية والتحديث خلال المحاكاة محلية، وتتجاهل الردود القديمة. البيانات في ذاكرة التبويب فقط، بلا تخزين متصفح أو SQL. بقية أقسام البوابة تواصل اتصالها المعتاد. **إنهاء محاكاة Outlook** أو **مسح المحاكاة** يعيد الاتصال؛ إعادة تحميل الصفحة تزيل العينات. كل هذا يتبع `Diagnostics:SimulationEnabled` ولا يحتاج تغيير API أو SQL. العينات تختبر شكل الواجهة وسلوكها، ولا تثبت صلاحيات Exchange أو وصول إشعارات EWS الفعلية.

التحقق: `node CompanyPortal/tools/verify-email.mjs` و`node CompanyPortal/tools/verify-schedule.mjs` يشملان الحالات، تجاهل الردود القديمة، عدم إنشاء طلبات/قنوات في المحاكاة، استعادة الحقيقي، وعدم تسجيل مستمع المحاكاة عند غياب أداة MVC.
