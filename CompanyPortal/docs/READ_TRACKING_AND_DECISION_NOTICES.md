# قراءة المحتوى والتنويه والتنبيهات

## السلوك

- القرارات، والتنويه، والتنبيهات تفتح ملف PDF نفسه من مصدر القرارات المصرح به.
- فتح القرار من أي قائمة يسجّل قراءته مرة واحدة للموظف. «عرض الكل» أو فتح قائمة أو المرور عليها لا يسجّل القراءة.
- علامة «جديد» تعني أن المادة لم تُقرأ بعد. القراءة تزيل العلامة من جميع مواضع القرار، ولا تخفيه قبل نهاية فترة العرض.
- التنويه يعرض افتراضيًا نوع «تنويه»، والتنبيه نوع «إعلان»، لمدة سبعة أيام من تاريخ النشر. يستطيع المسؤول تغيير الأنواع والمدة.
- الزر الموجود في رأس البوابة يظهر القسمين؛ يبقيان مخفيين افتراضيًا كما في السابق. إغلاق × في التنويه يخفي القرار المعروض نهائيًا لهذا الموظف من التنويه فقط، ويعرض التالي إن وجد. يبقى القرار في القرارات، ولا يعتبر الإغلاق قراءة. إغلاق التنبيه يخفي قسمه لهذه الصفحة فقط، ولا يخفي القسم الآخر.
- عنوان بطاقة التنويه يعرض نوع القرار الفعلي، مثل «تعميم»، بنفس تنسيق الشارة.
- لا تتغير صلاحيات القرارات: `Legal.Decisions_getForUser` هو مصدر المواد المسموح بها، ويعاد التحقق عند فتح PDF وعند حفظ القراءة. إعدادات العرض لا تمنح صلاحية إضافية.

## الجداول والإجراءات

طبّق بالترتيب على قاعدة موجودة:

1. `Backend/Database/Scripts/032_SharedUserReads.sql`
2. `Backend/Database/Scripts/033_DecisionNotices.sql`
3. `Backend/Database/Scripts/034_AddCircularNoticeType.sql`
4. `Backend/Database/Scripts/035_UserDecisionDismissals.sql`

تحتفظ `Portal.UserDecisionDismissals` بالإخفاء حسب UserId وDecisionId وChannelId؛ التكرار لا يضيف سجلًا ولا يغير وقت الإخفاء. يستخدم API الإجراءين `Portal.UserDecisionDismissals_Get` و`Portal.UserDecisionDismissals_Dismiss`. طلب `POST /api/decisions/{id}/dismiss-notice` يحدد الموظف من حساب Windows ويتحقق من صلاحية القرار وفترة العرض، ولا يقبل UserId من المتصفح. يُستبعد ظهور التنويه من استجابة قائمة القرارات نفسها دون طلب إضافي من المتصفح. عند فشل الحفظ، تعود البطاقة مع رسالة لإعادة المحاولة. لا يتأثر سجل القراءة.

اختبار محلي: `Backend/tools/Test-DecisionDismissals.ps1` ينشئ قرارًا مؤقتًا فريد الاسم في قاعدة التطوير، ويتحقق من الحفظ والتكرار والصلاحيات وبقاء القرار وPDF وحالة القراءة، ثم يزيل بيانات الاختبار المحددة فقط. يلزم نشر API والواجهة مع migration035؛ نسخة Setup الجديدة تشملها، والتصديرات التاريخية لا تتغير.

`Mstr.ContentType`: المفتاح `ContentTypeID` وهوية النوع الثابتة؛ الاسم للعرض فقط، ولا يوجد `ContentTypeKey`.

| ContentTypeID | ContentTypeName | مصدر ContentId |
| --- | --- | --- |
| 1 | المجلات | MagazineID من Portal.Magazines_GetAll |
| 2 | القرارات | DecisionId من Legal.Decisions_getForUser |

`Portal.UserReads`: `UserReadID` bigint identity، ثم `UserId` و`ContentTypeID` و`ContentId nvarchar(200)` و`ReadAt datetime DEFAULT GETDATE()`، وآخر عمود `Active bit DEFAULT 1`. قيد فريد على `(UserId, ContentTypeID, ContentId)` يمنع التكرار. `ReadAt` تاريخ أول قراءة؛ تكرار الفتح لا يعدّله. إعادة تفعيل سجل معطّل تسجّل وقت إعادة القراءة.

`ContentId` هو معرّف السجل الأصلي، وليس رقمًا يُنشأ عند الضغط. ترسل الـAPI الأرقام بصيغة موحّدة دون أصفار إضافية. لا تعِد استخدام معرّف لمادة مختلفة. تغييرات اسم/ملف المادة بنفس المعرّف لا تعيدها إلى غير مقروءة؛ إنشاء إصدار جديد يستلزم معرّف مادة جديدًا.

`Portal.UserReads_Get` و`Portal.UserReads_MarkRead` هما عقدا التخزين. لا توجد نقطة API عامة تقبل UserId أو نوع محتوى عشوائيًا. المستخدم يؤخذ من Windows NTName ويحوَّل إلى UserId عبر إجراء الأمن الموجود.

ترحّل 032 سجل `Portal.UserMagazineReads` مرة واحدة مع تواريخه وحالته. يبقى الجدول القديم أرشيفًا لا يكتب التطبيق إليه؛ إجراءات المجلات القديمة تعيد التوجيه إلى التخزين المشترك لتجنب التكرار. إعادة تشغيل 032 لا تعيد استيراد الأرشيف.

`Portal.DecisionNoticeSettings`: إعداد مستقل لكل قناة (1 تنويه، 2 تنبيه)، الأنواع المختارة في مصفوفة JSON محدودة، ومدة 1–365 يومًا، وActive وLastChangeAt.

`Portal.DecisionNoticeWindows`: استثناء لكل قناة وDecisionId، من/إلى اختياريان معًا، وIsHidden. الاستثناء لا يتجاوز شرط النوع المختار أو الصلاحيات. ترك التاريخين فارغين يعيد مدة تاريخ النشر. آخر حفظ معتمد، والتواريخ لا تتغير عند حفظ القيم نفسها.

الإجراءات: `Portal.DecisionNotices_Get` (نتيجتان: الإعدادات ثم الاستثناءات)، `Portal.DecisionNotices_Save`، `Portal.DecisionNoticeWindows_Save`. جميع تغييرات البيانات عبر SPs.

## الإدارة والتوقيت

- `/admin/notices`: إدارة التنويهات.
- `/admin/alerts`: إدارة التنبيهات.
- اختيار عدة أنواع، تشغيل/إيقاف، مدد سريعة 4 و7 و14 و30 يومًا، وفترة خاصة أو إخفاء قرار محدد، واستعادة المدة العامة.
- القرارات المعروضة للمسؤول هي التي تسمح بها صلاحياته الحالية؛ نوع غير موجود بعد يظهر إذا كان محفوظًا في الإعدادات.
- التاريخان في الإدارة وتواريخ النشر المصدرية هي أوقات عُمان المحلية، دون لاحقة منطقة زمنية في حقول الإدخال. الـAPI يعيد أوقات الفترات مع `+04:00`.
- بداية العرض مشمولة والنهاية غير مشمولة: `FromAt <= الآن < ToAt`. تواريخ الاستثناء المستقبلية مدعومة للمواد المنشورة، ويحدّث مؤقت محلي العرض عند البداية والنهاية دون استدعاء API دوري.
- يلزم تحديث الصفحة/تحديث القرارات لظهور قرار نُشر حديثًا أو إعداد إداري تغيّر بعد تحميل الصفحة؛ ليست هذه خدمة إشعارات فورية للقرارات.

## الطلبات والأداء

- نفس GET `/api/decisions` يرجع HasRead وفترات القناتين مع قائمة القرارات. لا يوجد GET إضافي لكل بطاقة أو لكل قرار أو لكل تنبيه.
- GET المجلات الموجود يرجع حالة قراءتها من الجدول المشترك. يظل سلوك القراءة المرئية للمجلة كما هو.
- طلب POST غير متزامن واحد لكل مادة غير مقروءة في الصفحة، بعد الفتح، مع مهلة اتصال. إعادة الفتح من قائمة أخرى لا تنشئ طلب كتابة آخر. لا تُخزّن قائمة قراءات الموظف في localStorage.
- فهرس المفتاح الفريد يخدم الاستعلام حسب الموظف والنوع. التسجيل بقفل مفتاح ومعاملة يمنع التكرار عند الفتح المتزامن من تبويبات مختلفة.
- نداءات SQL الإضافية ثابتة للقائمة، وليست بعدد المواد. عرض الصفحة لا ينتظر حفظ القراءة. لا يوجد polling لحالة القراءة.
- عند ترك الصفحة ثم العودة، تعاد قراءة قائمة القرارات المصرح بها وفق دورة الصلاحيات الموجودة سابقًا. نجاح القراءة محفوظ في ذاكرة الصفحة لمنع تكرار الكتابة.
- عند فشل حفظ القراءة تبقى غير مقروءة، ولا يعاد الإرسال تلقائيًا؛ يمكن تحديث الصفحة ثم إعادة فتح المادة. فتح PDF نفسه يعمل بشكل مستقل.
- هذا لا يغني عن اختبار تحميل على بيئة IIS/SQL الفعلية قبل اعتماد آلاف المستخدمين. لم ينفذ اختبار آلاف الاتصالات المتزامنة محليًا.

## الاختبارات والنقل

`Backend/tools/Test-SharedReads.ps1` يختبر API والتكرار وتواريخ no-op والتحقق من المدخلات وSwagger. يحفظ الصفوف التي أنشأها الاختبار ويحذف تلك الصفوف المحددة فقط، ولا يحذف تاريخًا سابقًا. `Test-MagazineReads.ps1` أصبح مدخلًا لنفس فحوص المجلات/التخزين المشترك.

`Backend/tools/Test-SharedReads.sql` يختبر عزل الموظف والنوع والحفظ المتكرر والاستثناءات والإخفاء والاستعادة داخل معاملة تُلغى بالكامل.

`Development/016_SeedDecisionNotices.sql` يضيف مثالين محليين من نوع تنويه وإعلان إلى قاعدة LegelAffairs المعلّمة للتطوير فقط، باستخدام ملفات PDF العينات الموجودة؛ ليس سكربت نقل للمصدر الداخلي.

## تحديث واجهة القرارات والتحديث التلقائي (034)

- لا تظهر كلمة جديد في قائمة القرارات: العنوان غير المقروء خمري `#7d243c`، والمقروء أسود `#000`، مع وصف القراءة لقارئ الشاشة. تبقى علامة جديد في التنويه والتنبيه بحسب حالة القراءة.
- أُزيل عرض الكل من التنويه، وأضيف زر × لإغلاق القسم لهذه الصفحة. يعيد زر الرأس إظهاره عند إيقاف العرض وتشغيله. أسهم صغيرة تتنقل بين عدة تنويهات؛ الإغلاق والتنقل لا يسجلان قراءة.
- تضيف 034 النوع تعميم مرة واحدة إلى اختيارات التنويه مع حفظ بقية الأنواع والمدة والحالة. علامة الترحيل تمنع إعادة الإضافة إذا أزاله المسؤول عمدًا لاحقًا. نوع المصدر الحالي نصي وليس جدول أنواع؛ Development017 يضيف قرار تعميم إلى قاعدة العينات المعلمة فقط.
- حقل بحث محلي في العنوان والنوع، يدعم الكلمات بأي ترتيب وتطبيع العربية وتأخير 150ms ومسح البحث وEscape. لا يجري أي طلب API أثناء الكتابة.
- أزيل زر تحديث القرارات. تجري قائمة واحدة مشتركة للقرارات/التنويه/التنبيه تحديثًا بعد نحو 60–65 ثانية من اكتمال الطلب السابق، والصفحة ظاهرة فقط. لا يوجد طلب لكل بطاقة. التحديث يحفظ البحث والتصنيف ولا يعيد رسم البيانات إذا لم تتغير، ولا ينشئ قراءة جديدة.
- عند أخطاء الاتصال تؤخر إعادة المحاولة تدريجيًا حتى خمس دقائق. يحتفظ فشل الاتصال العابر بالقائمة مع رسالة تعذر التحديث؛ رفض الهوية/التسجيل يمسح المحتوى. عند إخفاء الصفحة يُوقف المؤقت وتُمسح البيانات المصرح بها، ويجري تحميلها عند العودة، كما في دورة الصلاحيات السابقة.
- هذه الآلية تحقق تحديثًا تلقائيًا دوريًا، وليست وصولًا فوريًا. لا تحتاج SignalR. ربط دفع موحد لاحقًا عبر SSE أو SignalR يحتاج كذلك آلية موثوقة لاكتشاف تغييرات قاعدة المصدر الخارجية؛ مجرد إضافة مكتبة اتصال لا يكشف تلك التغييرات. البريد الحالي يحتفظ باتصال SSE الموجود دون تغيير.
- Setup الجديد يشمل001–034؛ لترقية قاعدة موجودة طبّق034 فقط بعد032–033. لا تعِد تشغيل Setup على قاعدة موجودة.

## التعديل الأحدث للبحث والاختبارات

البحث الآن بالعنوان فقط؛ اختيار النوع عبر قائمة منسدلة مستقلة بدل أزرار الأنواع. تتوفر محاكاة قرارات وتنويه وتنبيه وأخبار/أخبار عاجلة بإعداد frontend مستقل، دون بيانات SQL أو قراءات وهمية محفوظة. المرجع: [FRONTEND_SIMULATION.md](FRONTEND_SIMULATION.md).

## الإظهار التلقائي الأحدث

بعد أول تحميل، وصول قرار غير مقروء جديد ومصرح به في فترة قناة نشطة يفتح التنويه أو التنبيه تلقائيًا وفق أنواع الإدارة؛ لا يعتمد على الاسم تعميم وحده. المصدر يُفحص بالتحديث الدوري الموجود، وليس SignalR. مواد التحميل الأول لا تفتح القنوات تلقائيًا، حفاظًا على الإخفاء الافتراضي. تُتبع هوية القناة/المادة في ذاكرة الصفحة لتجنب إعادة الإظهار لنفس القرار، مع دعم بداية فترة عرض مستقبلية.

GET /api/decisions/notice-rules نقطة قراءة للمحاكاة فقط، تعيد أنواع القنوات وحالتها ومدتها بعد التحقق من الحساب. لا تضيف بيانات حساسة أو صلاحيات ولا تقبل أي كتابة. انشر API وfrontend الجديدين معًا؛ لا يلزم SQL جديد لهذا التعديل.

## استقلال ظهور التنويه والتنبيه

لكل قناة حالة فتح وإغلاق مستقلة في ذاكرة الصفحة. وصول مادة جديدة يفتح القنوات المطابقة لنوعها في إعدادات الإدارة فقط؛ وجود قرارات قديمة في قناة أخرى لا يفتحها تلقائيًا. إغلاق تنبيه يخفي قسم التنبيهات كاملًا، وليس المادة الحالية فقط. وصول تنويه جديد لا يعيد فتح تنبيه أغلقه المستخدم، والعكس كذلك. إذا ظهرت القناتان يبقى التنويه أولًا ثم التنبيه وفق ترتيب عناصر الصفحة.

زر الرأس ما زال يتيح إظهار/إخفاء القنوات يدويًا. إذا اختار المسؤول النوع نفسه في القناتين، فظهوره فيهما يكون نتيجة هذا الاختيار الصريح. لا تُفرض قناة إضافية من المتصفح.

تستخدم المحاكاة نفس القنوات المطابقة، ويغلق «مسح المحاكاة» القناتين ويزيل المواد الوهمية. حجم خط قائمة أنواع القرارات وقائمة نوع المحاكاة أصبح14px.
